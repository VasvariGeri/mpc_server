Átnéztem a repo állapotát: jelenleg lényegében zöldmezős projekt, csak README.md van benne. A MEK oldal alapján a szervert érdemes vékony, jól tesztelt MCP-adapterként megírni: ne próbáljon „okos chatbot” lenni, hanem stabil keresőprimitíveket adjon az agentnek.

Források: MEK egyszerű keresés, MEK összetett keresés, MEK teljes szövegű keresés.

Javasolt architektúra
Python MCP szerver src/mek_mcp/ alatt, nagyjából így:

server.py: MCP belépési pont és tool-regisztráció
client.py: MEK HTTP kliens, timeout, user-agent, encoding kezelés
schemas.py: Pydantic modellek keresési inputokra és találatokra
parsers.py: MEK HTML találati oldalak feldolgozása
fields.py: összetett kereső mezőinek whitelistje
tools.py: MCP tool implementációk
tests/fixtures/: mentett MEK HTML minták
tests/: parser, kliens és tool unit tesztek
MCP toolok
Első körben ezeket építeném:

mek_simple_search
Mezők: title, subject, creator, mek_id, limit, offset.
A MEK paraméterei: dc_title, dc_subject, dc_creator, id, size, from.

mek_full_text_search
Mezők: query, broadtopic, limit, offset.
Hasznos a Duna/AI/szabad szavas példákhoz. Visszaad snippetet és találati hely URL-t is.

mek_advanced_search
Legfeljebb 5 feltétel: field, query, majd köztük and/or/not.
MEK oldalon: s1..s5, m1..m5, muv1..muv4, szerint, ekezet.

mek_browse_index
A „LISTA” funkció MCP-s megfelelője kontrollált alakokhoz, például tárgyszóvariánsokhoz. Ez kell a „néprajz tárgyszóalakok” típusú kérdésekhez.

mek_get_record
MEK rekordoldal lekérése egy találat URL-je vagy MEK ID alapján, hogy az agent pontosabb bibliográfiai adatokat tudjon használni.
